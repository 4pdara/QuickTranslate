# צעדים הבאים — QuickTranslate Desktop

מסמך זה מתעדכן בסוף כל milestone עם המצב הנוכחי והצעד המומלץ הבא.

## מצב נוכחי (עדכון אחרון — 2026-06-28, milestone M9)

התיקון הראשון לקיצור המקשים (M8) לא היה מספיק — המשתמש דיווח ש"לא נמצא
טקסט מסומן" מופיע גם כשהיה טקסט בלוח. תוקן שורש הבעיה האמיתי:

- **שורש הבעיה:** ברגע ש-Ctrl+Shift+T נדלק, Shift (ולעיתים Ctrl) עדיין
  לחוצים פיזית. שליחת Ctrl+C סינתטי באותו רגע יכולה לצאת בפועל כ-
  **Ctrl+Shift+C** (כי ה-OS עדיין רואה Shift לחוץ) — שאף אפליקציה לא
  מפרשת כ"העתק". זו הסיבה שהלוח "לא השתנה" אצל המשתמש.
- **התיקון:** לפני שליחת Ctrl+C, משחררים סינתטית Shift ו-Alt
  (`send_clean_copy_keystroke`), עם השהיה קצרה (120ms) לפני כן ועוד כמה
  ms בין שלבי הקליק. הפולינג על הלוח הוארך מ-700ms ל-1400ms (50ms בכל
  פעם). כל הלכידה רצה ב-thread נפרד כדי לא לחסום את ה-hotkey event loop.
  הפופאפ מוצג **רק אחרי** שהלכידה הסתיימה (לא לפני) — כך שאין סיכון
  שהפופאפ גוזל פוקוס מהאפליקציה שבה המשתמש סימן טקסט.
- **`allowUnchangedClipboardFallback` שונה לברירת מחדל `true`** (לפי בקשת
  המשתמש) — כך שאם הלכידה לא תפסה שינוי, האפליקציה מתרגמת את מה שכבר בלוח
  במקום להציג שגיאה. כשזה קורה, מוצגת הערה בפופאפ: "הטקסט תורגם מהלוח כי
  הלוח לא השתנה." ההגדרה עדיין גלויה וניתנת לכיבוי בהגדרות.
- נוספה דיאגנוסטיקה ב-debug build (אורכי טקסט בלבד, לא תוכן): foreground
  window captured, copy command sent, clipboard changed, fallback used,
  capture duration ms.
- אומת: `tsc --noEmit`, `npm run build`, `cargo check`, ו-`npm run tauri build`
  (release מלא + installer) — כולם עוברים.

## מה לא נבדק עדיין (דורש בדיקה ידנית של המשתמש)

- **הבדיקה הקריטית ביותר:** לסמן טקסט אמיתי בדפדפן/Notepad ולבדוק ש-
  Ctrl+Shift+T מתרגם את הטקסט שסומן (לא תוכן ישן, ולא שגיאת "לא נמצא טקסט").
  אם זה עדיין נכשל — יש לדווח באילו אפליקציה ספציפית (יש אפליקציות עם
  טיפול קליפבורד לא סטנדרטי), ואפשר להפעיל debug build (`npm run tauri dev`)
  ולבדוק את שורות הדיאגנוסטיקה בטרמינל.
- בדיקת "תרגם גם אם הלוח לא השתנה" בשני המצבים (דלוק/כבוי) לפי 3 התרחישים
  ב"הוראות בדיקה ידנית" למטה.
- לוודא שהיסטוריית הלוח של Windows (Win+V) לא נפגעה אחרי שימוש בקיצור.

## הוראות בדיקה ידנית (מדויקות)

**A. טקסט מסומן (המקרה הנפוץ):**
1. שים טקסט ישן ולא קשור בלוח (Ctrl+C על משהו).
2. סמן טקסט **אחר** ב-Notepad/דפדפן (בלי להעתיק אותו ידנית).
3. לחץ Ctrl+Shift+T.
4. **צפוי:** מתורגם הטקסט שסימנת, לא התוכן הישן.

**B. בלי טקסט מסומן:**
1. אל תסמן טקסט.
2. שים טקסט בלוח (Ctrl+C על משהו).
3. לחץ Ctrl+Shift+T.
4. **צפוי עם fallback מופעל (ברירת המחדל):** מתורגם תוכן הלוח, עם ההערה
   "הטקסט תורגם מהלוח כי הלוח לא השתנה."
5. **צפוי עם fallback כבוי:** שגיאה "לא נמצא טקסט מסומן לתרגום. סמן טקסט ונסה שוב."

**C. טקסט מסומן זהה לתוכן הלוח:**
1. העתק טקסט ללוח (Ctrl+C).
2. סמן את **אותו טקסט בדיוק** (בלי להעתיק שוב).
3. לחץ Ctrl+Shift+T.
4. **צפוי עם fallback מופעל:** הטקסט מתורגם (כי אין הבדל בין הלוח הישן
   לחדש, אז ה-fallback קופץ פנימה — זו ההתנהגות הנכונה לתרחיש הזה).

## הצעד המומלץ הבא

1. בדיקה ידנית של שלושת התרחישים למעלה.
2. אם עדיין יש כשלים — לרוץ עם `npm run tauri dev` (debug build) ולשלוח את
   שורות הדיאגנוסטיקה מהטרמינל (אורכים בלבד, לא תוכן).
3. לעבור למילסטון הבא: קיצור מקשים דינמי בלי הפעלה מחדש, ו/או פופאפ סמוך
   לעכבר.

## פתוחות / לאישור משתמש

- ברירת המחדל הנוכחית היא `libretranslate` (דורש הזנת כתובת שרת בהגדרות) —
  לאשר שזה הכיוון הרצוי, או לשנות ברירת מחדל לספק שעובד מהקופסה.
- שם תצוגה סופי לאפליקציה (כרגע `QuickTranslate` / identifier
  `com.quicktranslate.desktop`).
